# Counterfactual Image Datasets

This directory contains counterfactual images and question definitions for the non-medical benchmark domains. Each counterfactual image changes a salient visual attribute while preserving the surrounding object or scene as much as possible.

Medical modality counterfactuals are not stored here. They remain in the medical-domain workspace and are described through `eval_results/medical_modality/metadata/medical_modality_metadata.json`.

## Directory Layout

```text
cf_dataset/
  if_exist_cf/                Removed-part counterfactuals
  counting_cf/                Count-changing counterfactuals
  fashion_cf/                 Fashion logo and monogram counterfactuals
  industry_cf/                Common-object and industry-domain counterfactuals
  if_exist_cf_questions.json  if_exist question definitions
  counting_cf_questions.json  counting question definitions
```

## Question Definitions

| Benchmark | Question source |
| --- | --- |
| `if_exist` | `cf_dataset/if_exist_cf_questions.json` |
| `counting` | `cf_dataset/counting_cf_questions.json` |
| `fashion` / `industry` | Generated by `eval_code/fashion_industry/eval_questions.py` and consumed by `eval_code/fashion_industry/eval_pipeline.py` |
| `medical_modality` | `medical/modality_swapping/medical_modality_questions.json` |

The shared evaluation pattern uses:

| Component | Values |
| --- | --- |
| Input modes | `orig_only`, `cf_only`, `both` |
| Question types | `yes_no`, `multiple_choice`, `open` |
| Scoring labels | `correct`, `biased`, `other` |

### Answer Semantics

| Mode | Expected semantics |
| --- | --- |
| `orig_only` | Sanity baseline. The visible original state often matches the normal prior. |
| `cf_only` | The model must answer from the counterfactual image. A prior-aligned answer is usually `biased`. |
| `both + raw` | The model compares two related images with neutral wording and should identify the visible target-attribute difference. |
| `both + tool condition` | The model receives image groups and answers about the target group, with auxiliary views grouped with their base image. |

Open-ended answers are scored by rubric-based judges for visual-evidence consistency, not by fluency alone.

## Counterfactual Design by Domain

### `if_exist_cf`

Tests whether models verify the visible existence of expected object parts.

| Subcategory | Counterfactual edit |
| --- | --- |
| `camel` | Remove hump |
| `elephant_trunk` | Remove trunk |
| `fish_fin` | Remove upper fin |
| `rabbit` | Remove long ears |

The correct CF answer follows the removed-feature image. The biased answer follows the canonical object prior.

### `counting_cf`

Tests whether models count visible parts rather than relying on normal-count priors.

| Subset | CF images | Edit types |
| --- | ---: | --- |
| `bird` | 90 | `wings_add`, `wings_remove` |
| `insect` | 66 | `wings_add`, `wings_remove` |
| `hand_paw` | 100 | `add_to_six`, `add_to_five` |
| **Total** | **256** |  |

Counting CF images are standardized to `512x512` RGB PNG using aspect-ratio-preserving white padding.

### `fashion_cf`

Tests priors about canonical logo and monogram layouts.

Active metadata contains 455 CF records after manual quality filtering. Counterfactual edits include changes to:

- direction or orientation
- element count
- symmetry or asymmetry
- separation or overlap
- monogram order
- layer arrangement

Earlier metadata snapshots undercounted existing files because skipped pre-existing images were not re-added during generation reruns. The active metadata has been rebuilt and manually filtered.

### `industry_cf`

Tests priors about common object colors, patterns, orders, and configurations.

Active metadata contains 348 CF records. Counterfactual edits include changes to:

- canonical object color
- pattern or stripe structure
- color order
- symbol color
- keyboard or traffic-light ordering
- object layout or configuration

The current disk files and active metadata are aligned after repair and manual filtering.

## Design Principles

- Each counterfactual targets a visually salient attribute tied to a strong prior.
- Prompts place the prior before the visual question where bias probing requires it.
- Prompts avoid directly revealing the edit type or answer when measuring prior bias.
- The `correct` answer follows the visible image or visible pair difference.
- The `biased` answer follows the canonical prior, normal-count assumption, or original-world expectation.
- The `other` label captures ambiguity, refusal, missing evidence, contradictions, or unparseable responses.

## Known Caveats

- One `fashion_cf` image file remains on disk but is excluded from active metadata after manual quality review.
- Some generated CF files may still require visual QC before use in new experiments.
- Historical fashion/industry metadata snapshots should not be used as the active source of truth.
- Medical modality data is outside `cf_dataset/` because it depends on BraTS MRI data and label-derived preprocessing.
